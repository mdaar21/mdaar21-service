## AI مفعل — تحقق فعلي 21 أكتوبر2026

اكتمل إعداد متغيرات الخدمة الستة ونشرها في النسخة `6ad8e404b09d69f2e2b5670a`. حُفظ بديل رمز Redis من المالك في Netlify كسر production دون نسخه إلى Git أو ملفات محلية أو أصول المتصفح. انتهى عائق EVAL السابق: نجح تسجيل الدخول عبر الحصص الفعلية HTTP200، وCookie آمن، وطلب Groq نصي فعلي HTTP200. نجح التعرف على الجلسة والخروج؛ يُرفض طلب AI دون جلسة401. إثبات حد تسجيل الدخول عبر اتصال HTTP مستمر: أول خمس محاولات خاطئة401 ثم السادسة والسابعة429 مع Retry-After60. تفاصيل التنفيذ دون القيم في ai-live-validation.json. محاولة الحصص الأولى عبر اتصالات منفصلة كانت غير حاسمة؛ الاختبار المستمر في الدقيقة نفسها حسم النتيجة. لم يُختبر تنافس متعدد المناطق أو حمل مرتفع أو نموذج الصور الحقيقي.

أجاز المالك استخدام AI دون access code. النشر الحالي يفعّل AI_PUBLIC_ACCESS=true؛ يكفي تفعيل الموافقة من الإعدادات ثم إرسال الطلب. تبدأ جلسة آمنة تلقائياً دون إدخال رمز، وتستمر حصص Redis على إنشاء الجلسات وكل طلب AI. اختبارات58 وحدة/تكامل و12 سيناريو متصفح ناجحة. اختُبر أيضاً تدفق Chromium للجوال برد Groq حقيقي دون رمز: بقيت الطلبات غائبة قبل الموافقة، ونجح بدء Cookie الآمن والرد وإلغاء الموافقة. استُخدم HTTP relay موثوق بشهادة المنصة لأن مخزن شهادات Chromium لا يحتوي شهادة وكيل البيئة؛ لم تُزيَّف ردود API ولم يُعطَّل TLS. التقرير public-ai-live-browser.json يوضح النطاق.

الوضع الخاص لا يزال متاحاً عند تعطيل AI_PUBLIC_ACCESS؛ تبطل جلسات public حينها. رمز الدعوة الخاص محفوظ في لوحة Netlify الموثقة ولا يُعاد عبر API عام. مفاتيح Groq وRedis والتوقيع والحصص موسومة secret. لا تُكرر القيم التي شاركها المالك في التقارير؛ يوصى بتدوير بيانات Redis وتحديث القيمة الآمنة مباشرة دون نشرها في الدردشة. لم يُختبر إلغاء مفتاح Groq القديم المكشوف من ZIP، ولا تُستخدم قيمته في التنفيذ الجديد.
