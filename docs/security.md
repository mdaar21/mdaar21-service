# مراجعة أمان مدار — تنفيذ P0

هذه تغييرات تطوير على `codex/mdaar-global-upgrade` وليست عملية نشر. لم يُدوّر أي مفتاح حقيقي من داخل هذا العمل.

## الأسرار والإعداد قبل تفعيل الذكاء الاصطناعي

الـZIP الأصلي احتوى مفتاح Groq مكشوفاً. ألغِ المفتاح القديم من لوحة Groq وأنشئ مفتاحاً جديداً. لم تُنسخ دالة ZIP القديمة إلى المستودع. لا ترسل أي قيمة سرية في المحادثة أو Pull Request.

اضبط القيم التالية **داخل Netlify Functions فقط**، ويفضل تقييدها بسياق النشر المقصود. لا تجعلها متاحة لبناء أصول المتصفح، ولا تضعها في `public` أو Git أو ملفات اختبار:

| المتغير | الوظيفة |
| --- | --- |
| `GROQ_API_KEY` | مفتاح Groq الجديد |
| `UPSTASH_REDIS_REST_URL` | رابط HTTPS لقاعدة Upstash Redis، على مضيف ينتهي بـ`.upstash.io` |
| `UPSTASH_REDIS_REST_TOKEN` | رمز REST يسمح بأوامر EVAL وGET وINCR وEXPIREAT |
| `RATE_LIMIT_SALT` | قيمة عشوائية سرية لا تقل عن 32 محرفاً لتشفير معرفات IP أحادي الاتجاه بـHMAC |
| `AI_SESSION_SECRET` | قيمة عشوائية سرية لا تقل عن 32 محرفاً لتوقيع جلسات الدعوة |
| `AI_ACCESS_CODE` | رمز دعوة سري لا يقل عن 12 محرفاً؛ يوصى بقيمة عشوائية طويلة لا تقل عن 24 محرفاً |

إعدادات اختيارية: `GROQ_MODEL`, `GROQ_VISION_MODEL`, `AI_ALLOWED_ORIGINS` (أصول كاملة مفصولة بفواصل)، `LIMIT_PER_IP` (25 طلب AI/يوم افتراضياً)، `LIMIT_PER_DAY` (400 طلب AI/يوم لجميع المستخدمين)، `LIMIT_PER_MINUTE` (5 طلبات AI/دقيقة لكل IP). القيم غير الصحيحة لا تُعطّل الحماية؛ ينتج عنها رفض آمن للخدمة. لا حاجة لمفتاح AI لتشغيل الحاسبة والدفتر المحلي والتمارين.

## ما ينفذه الخادم

- مسار `/api/session` يستقبل `POST {"code":"…"}` بعد التحقق من البنية ومعدل المحاولات. لا يعيد رمز الدعوة. يعيد Cookie باسم `__Host-mdaar_session` بخصائص `HttpOnly; Secure; SameSite=Strict; Path=/` وعمر ثابت 12 ساعة. تتم المقارنة بتجزئتين ثابتتي الحجم باستخدام `timingSafeEqual`.
- `GET /api/session` يعيد حالة تسجيل الدخول فقط، و`DELETE /api/session` يحذف Cookie المتصفح. لا تُخزّن كلمة الدعوة في localStorage. يلزم HTTPS خارج localhost.
- `/api/ai` يتطلب جلسة موقعة وصالحة، ثم يتحقق من الطلب ويطبق الحصص الموزعة قبل أي استدعاء لـGroq. لا توجد طريقة تجاوز في بيئة الإنتاج أو رمز مشاركة مضمّن في JavaScript.
- هذا **تحكم وصول برمز دعوة مشترك**، وليس حسابات شخصية أو إثبات هوية. من يحصل على الرمز يستطيع طلب جلسة. لا توجد مزامنة مستخدمين أو صلاحيات فردية. تسجيل الخروج يحذف Cookie الحالي؛ الرمز المسروق يبقى صالحاً إلى انتهاء مدته. لتصفير جميع الجلسات غيّر `AI_SESSION_SECRET`. عند تسريب رمز الدعوة، غيّر الرمز والسر معاً.
- Redis يشغّل Lua ذرياً لفحص ثلاث حصص وزيادتها معاً: لكل IP/يوم، إجمالي/يوم، ولكل IP/دقيقة. الأسماء تتضمن hash tag موحداً لتوافق التنفيذ الذري. الحماية مشتركة بين استدعاءات Netlify، ولا تعتمد على ذاكرة العملية.
- محاولات الدخول لها مساحة مفاتيح منفصلة: 5/دقيقة و20/يوم لكل IP و200/يوم إجمالاً. منع الدخول عند تعطل Redis مقصود.
- يُستخدم `context.ip` الموثوق من Netlify؛ لا يعتمد الخادم على رأس IP يرسله العميل. تُخزّن معرفات HMAC تتغير يومياً، دون IP صريح في مفاتيح Redis. تنتهي المفاتيح بعد نهاية نافذتها بدقيقة. هذا تقليل للبيانات، وليس ادعاء إخفاء هوية كامل.
- غياب المفاتيح أو إعداد الجلسة أو Redis يمنع استدعاء المزود (`503`). الجلسة غير الصالحة تعطي `401`، وتجاوز الحصة يعطي `429`.
- طلب JSON أقصاه 2,100,000 بايت؛ prompt أقصاه 8,000 محرف. الصورة Base64 بصيغة JPEG، مع فحص canonical encoding وتوقيع البداية والنهاية وحد 1,500,000 بايت بعد الفك. هذا فحص نقل وحجم، وليس فحصاً كاملاً لمحتوى JPEG أو ضماناً لوجود طعام.
- قراءة جسم الطلب محدودة بالحجم والوقت. استجابات المزود محدودة الحجم، وJSON المتداخل محدود العمق والعناصر والمفاتيح؛ تُرفض مفاتيح prototype والأرقام غير المنتهية. على كل ميزة في المتصفح التحقق من مخططها المتوقع واستخدام `textContent` أو الهروب قبل HTML.
- استدعاءات Groq واستكشاف نموذج بديل تشترك في مهلة كلية واحدة 25 ثانية، مع إعادة محاولة واحدة فقط عند خطأ نموذج 400/404. لا تسجل الدالة النصوص أو الصور أو IP أو أسراراً أو أجسام أخطاء المزود.
- تُرفض استدعاءات المتصفح العابرة للأصول، ولا تُمنح CORS. فحص Origin إضافي ولا يُعامل بديلاً عن الجلسة.
- CSP يمنع scripts المضمنة ومصادر الشبكة غير المصرح بها، مع `nosniff` ومنع التأطير وسياسة مرجع وأذونات محدودة. السماح المؤقت بـ`unsafe-inline` يخص CSS لأن الواجهة الأصلية تستخدم سمات style؛ لا يشمل JavaScript. رؤوس Netlify الفعلية تحتاج تحققاً بعد نشر تجريبي مصرح به.

## البيانات والخدمات الخارجية

يحفظ المتصفح بيانات المستخدم المحلية. الطلبات التي يرسلها المستخدم تُرسل إلى دالة Netlify ثم إلى Groq؛ صورة الطعام وبيانات الطلب قد تكون حساسة، وإخفاء الوجوه والمعلومات الشخصية قبل الإرسال مطلوب. Redis يستقبل معرّفات الحصص المستعارة والعدادات، ولا يستقبل نص الوجبات أو الصور من هذا التنفيذ. قد يحتفظ مزودو الاستضافة والـAI ببيانات تشغيل وفق عقودهم وإعداداتهم؛ راجع سياساتهم قبل الإطلاق وسياسة الخصوصية مع مختص قانوني.

لا تُعرض أي نتيجة صورة بوصفها قياساً طبياً دقيقاً، ولا تُعامل قيمة مولدة بالذكاء الاصطناعي بديلاً لقاعدة غذائية موثقة. لم تُضف أنظمة متجر أو دفع.

## الاختبارات والحدود

شغّل `node --test tests/ai*.mjs`. تتضمن الاختبارات طلبات دالة حقيقية مع بدائل شبكة محكومة: JSON غير سليم، أحجام زائدة، صورة غير صالحة، أصول غير مسموحة، غياب الإعداد، رفض Redis، الحصص، نتائج سليمة وخاطئة، مهلة المزود، fallback، تسجيل الدعوة، Cookie، الانتهاء والعبث والدوران.

تم اختبار تركيب أمر Lua والـTTL ومعرفات HMAC عبر بدائل HTTP، **ولم يُنفّذ EVAL في Upstash حقيقي أو اختبار تنافس موزع**. يلزم فحص تكامل في سياق Netlify تجريبي مع أسرار آمنة قبل نشر الإنتاج: دخول فعلي، Cookie HTTPS، 6 طلبات دقيقةً للتأكد من الرفض، طلب Groq ناجح، وتعطيل Redis للتأكد من الفشل المغلق. اختبارات الشبكة الاصطناعية لا تثبت صلاحية مفاتيح أو نموذج أو فوترة أو إعدادات منصة حقيقية.

## الوضع العام بدون رمز دعوة

أجاز المالك استخدام AI دون إدخال access code. عند `AI_PUBLIC_ACCESS=true` (مطابقة حرفية فقط)، يعلن GET /api/session الوضع العام. يرسل المتصفح POST {"start":true} عند الضغط على إرسال والحاجة إلى جلسة، دون مربع موافقة منفصل؛ يبقى فحص Origin، والتحقق الصارم من الجسم، وحصة إنشاء الجلسات المشتركة قبل إصدار Cookie. لا يحتاج الوضع العام AI_ACCESS_CODE لكنه يتطلب توقيع الجلسة وRedis. الجلسة موسومة public وموقعة، وتبطل عند تعطيل الوضع العام. دون هذا الخيار يظل وضع الدعوات كما كان، والجلسات القديمة من نوع invite مدعومة.

طلب /api/ai دون Cookie يبقى401، وتُطبق حصص Redis على كل طلب معتمد، دون مسار بديل يتجاوز الحماية. إغلاق نافذة المساعد أثناء إنشاء الجلسة يلغي العملية ويمنع إعادة إرسال الطلب. المعدلات الافتراضية: إنشاء الجلسات20/IP/يوم و200 إجمالاً/يوم و5/IP/دقيقة؛ AI25/IP/يوم و400 إجمالاً/يوم و5/IP/دقيقة. الحصص من الخادم، ولا تمثل ضمان منع هجمات ذات عناوين متعددة.
